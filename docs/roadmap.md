# Roadmap

A summary of the epics and their issues, and what each delivers. Status is kept on the [board](https://github.com/users/sekoya-solutions/projects/4) and on the issues, not here.

## Outside the epics

- [#1](https://github.com/sekoya-solutions/sekoya-website/issues/1) Record the initial architecture decisions: the first nine [Architecture Decision Records (ADRs)](adr/README.md), from the framework to the repository and its licences, written before any code.
- [#46](https://github.com/sekoya-solutions/sekoya-website/issues/46) Reserve all rights on the whole repository: ADR 0009 records the change from MIT, and `LICENSE`, the README and the legal page say that the code is public to be read, not reused.
- [#64](https://github.com/sekoya-solutions/sekoya-website/issues/64) One layout shift rule for every end-to-end test: a shared helper records a page's layout shifts and checks their total against the one allowance for the font swap (0.001); the hero and font-swap tests use it, both with the font held back until the first paint, and a unit test fails on any test that observes layout shifts elsewhere.

## [Epic #8](https://github.com/sekoya-solutions/sekoya-website/issues/8): Foundation

Everything the pages build on.

- [#3](https://github.com/sekoya-solutions/sekoya-website/issues/3) Set up the repository and tooling: the Astro project (static output, TypeScript strict, Tailwind CSS 4) with an empty home page; Biome, Vitest, Playwright with axe, and the Markdown checks; a CI workflow that runs only the Markdown checks when every changed file is Markdown; the project rules in `AGENTS.md`, the README, the licences and this roadmap.
- [#4](https://github.com/sekoya-solutions/sekoya-website/issues/4) Host the site on Cloudflare Workers with previews: the repository connected to a Worker with static assets, built by Workers Builds, with production from `main` on `workers.dev` until launch and a preview per branch, both kept out of search engines; security headers, cache lifetimes and a per-page Content Security Policy; the end-to-end tests served by `wrangler dev`; and the [hosting setup](hosting.md) for the owner.
- [#5](https://github.com/sekoya-solutions/sekoya-website/issues/5) Add the brand assets: the logos for dark and light backgrounds, the themeable animated logo, the favicons and app icons, and the Outfit font with its licence, as provided.
- [#6](https://github.com/sekoya-solutions/sekoya-website/issues/6) Design tokens, fonts, base layout and theme: the brand tokens as CSS variables mapped into Tailwind, the self-hosted font, the base layout with header and footer shells, and the theme toggle.
- [#7](https://github.com/sekoya-solutions/sekoya-website/issues/7) Language scaffolding: French at the root and English under `/en/`, with the map of translated paths, the interface dictionaries, the FR | EN language switch, `hreflang` alternates with `x-default` on every page, the French typography helper, and a test that visits every route in both languages.
- [#29](https://github.com/sekoya-solutions/sekoya-website/issues/29) Keep the design references outside the repository: ADR 0009 records that the page mockups are never committed.

## [Epic #11](https://github.com/sekoya-solutions/sekoya-website/issues/11): Home page

- [#9](https://github.com/sekoya-solutions/sekoya-website/issues/9) Hero and logo growth animation: the inlined animated logo with its circuit extension, halo, travelling dot and dot grid, in pure CSS with nothing running under reduced motion; the copy in the first content collection, with `[TODO: …]` placeholder chips for the facts still to approve; and the calls to action, each shown once its page exists.

## [Epic #17](https://github.com/sekoya-solutions/sekoya-website/issues/17): Content pages

- [#12](https://github.com/sekoya-solutions/sekoya-website/issues/12) Offers page: at `/offres` and `/en/services`, the three offers from the `offers` collection in cards aligned row by row with CSS subgrid, each at the anchor the home teaser links to, then the three steps to start and the quiz band, each call to action shown once its page exists; and a test that finds no currency symbol or code on any built page.
- [#13](https://github.com/sekoya-solutions/sekoya-website/issues/13) Case studies: at `/realisations` and `/en/case-studies`, a card per case study aligned row by row with CSS subgrid, then the CV button once `public/cv.pdf` exists and a placeholder until then; a page per case study, made from its MDX file in the `caseStudies` collection with no code change, with the role and period, the context, what was done, the results (a result still to measure is a placeholder chip), the stack and a closing band; French typography and placeholder chips in MDX bodies; and the placeholder guard, `npm run check:todos`, which reports the placeholders left and the missing files in CI.
- [#14](https://github.com/sekoya-solutions/sekoya-website/issues/14) Portfolio: at `/portfolio` and `/en/portfolio`, a card per project from its MDX file in the `projects` collection, with no code change, in a grid of one to three columns where a card may span two, and a ghost card that fills the rest of the last row; filters by category in CSS only (radio buttons and `:has()`); a page per project with its figures, each dated and linked to its source, what it demonstrates, its screenshots and its stack; and, for Sekoya Transit, the playable demo behind a click-to-load facade, a small inline script that ADR 0005 now allows, with a notice and a link instead below 1280 px or on a touch screen; and each card of the home page's portfolio section now links to its project page.
- [#15](https://github.com/sekoya-solutions/sekoya-website/issues/15) About page and working with AI: at `/a-propos` and `/en/about`, from the `about` collection, who (with the brand avatar and a placeholder until a photo is added to the content), the values, what clients get, the technologies of today and of past experience, and, at the `#ia` anchor, how the work is done with AI: the tools, the four-step workflow and the guardrails, with links to the AGENTS.md files of Sekoya Transit and Sekoya Parts; then a closing band, each call to action shown once its page exists.
- [#16](https://github.com/sekoya-solutions/sekoya-website/issues/16) Contact page and legal notice: at `/contact` and `/en/contact`, the direct links (email, Malt, LinkedIn, GitHub) from the company's facts in one shared file, each address still to provide a placeholder with no link; the optional plain HTML form, rendered only when `PUBLIC_CONTACT_FORM_ACTION` is set and the legal notice names the service that receives the messages, with labelled fields, the browser's own validation, its messages linked to their fields, a honeypot and a consent checkbox, tested on a second build with a test address; the `sujet` query parameter, which preselects the subject through a small inline script that ADR 0005 now allows, and which the offers' buttons now carry; at `/mentions-legales` and `/en/legal`, the legal notice with the publisher and the host, what the site does with data (no cookie, analytics or third-party script) and the credits, each missing fact a placeholder; and a link to it in every page's footer.
- [#37](https://github.com/sekoya-solutions/sekoya-website/issues/37) Header navigation: the links to the main pages (offers, case studies, career, portfolio, about), each shown once its page exists, with the current page or section marked, and the contact button, in one row from 1280 px; below, a menu built on `<details>` that works with no JavaScript and with the keyboard, with the theme toggle and language switch kept in the bar.

## [Epic #20](https://github.com/sekoya-solutions/sekoya-website/issues/20): Interactive features

- [#18](https://github.com/sekoya-solutions/sekoya-website/issues/18) Career tree rings: at `/parcours` and `/en/career`, the positions from the `career` collection, each agreeing with its case study, as a trunk's cross-section whose ring geometry is computed at build time (one band per position, the oldest at the pith, one hairline per whole year), in dark wood or light sand wood with the theme; from 1024 px with scripting, the rings beside the panel of the selected position with the link to the case study, a tooltip, a legend in one row under both and a keyboard path, the ring sized on both the width and the height so the rings, the panel and the legend fit on one screen, the rings drawing themselves once from the pith outwards when they come into view, and drawn in full under reduced motion; below 1024 px or without JavaScript, the vertical timeline, the list of positions always in the page; and the header's career link.
- [#19](https://github.com/sekoya-solutions/sekoya-website/issues/19) Self-assessment quiz: at `/quiz` and `/en/quiz`, the ten questions from the `quiz` collection as a Preact island, one per step with native radio buttons and a keyboard path (1, 2, 3, Enter, Backspace); the scoring and the top three priorities in a pure function with unit tests; the result screen with the gauge, the level, the priorities and their advice, the matching offers read from the `offers` collection, and a call to action that preselects the contact page's subject, nothing stored or sent; without JavaScript, the questions as a printable checklist with the levels' table; and the quiz's links, now shown on the home, offers and contact pages and in every page's footer.

## [Epic #27](https://github.com/sekoya-solutions/sekoya-website/issues/27): Quality, SEO and launch

- [#21](https://github.com/sekoya-solutions/sekoya-website/issues/21) Lighthouse pipeline and footer scores: `npm run lighthouse`, which builds the site, serves it with `wrangler dev`, runs mobile Lighthouse three times on one French page per template and writes each page's medians and, as the site's figure, the lowest page median of each category, with the date, into `src/data/lighthouse.json`; the footer's "this site, measured" column with a ring per category and the date, or the measurement said pending when there is no file, and the link to the source code; the portfolio's card and page for this site, which read the same file; and the Lighthouse job in CI, the same measurement, which fails when a page is below 95 in any category.
- [#48](https://github.com/sekoya-solutions/sekoya-website/issues/48) Footer brand and navigation columns: the brand column with the horizontal logo, the tagline and the company line, whose registration comes from the company's facts; the navigation column with the links to the main pages, the quiz and contact, each shown once its page exists and the page shown marked; the three columns side by side from 1024 px and stacked on phones, with the copyright line and the legal notice under them.
- [#51](https://github.com/sekoya-solutions/sekoya-website/issues/51) Career page: no empty band between the pinned rings and the footer: in the pinned layout, the footer follows the rings' block directly, so at the bottom of the page the block has left the screen only by the footer's height, checked at several screen sizes; the other layouts and pages keep their spacing.
- [#53](https://github.com/sekoya-solutions/sekoya-website/issues/53) Responsive layout rules: ADR 0010, which allows only three width steps (48, 64 and 80 rem) and one height (45 rem) in media queries, makes layouts fluid between them, takes the scroll pinning off the career page, and lists the reference viewport sizes and the width sweep that every page must pass.
- [#55](https://github.com/sekoya-solutions/sekoya-website/issues/55) Career stage without scroll pinning: the rings draw once when they come into view, sized on both the width and the height, from 1024 px with scripting, with the panel's spacing tightened on short screens so the rings, the panel and the legend fit on one screen at every reference size of ADR 0010; the vertical timeline below 1024 px; and a normal scroll to the footer, with the page's usual spacing before it, in place of #51's pinned layout.

- [#54](https://github.com/sekoya-solutions/sekoya-website/issues/54) Media query guard and width sweep: a unit test that fails on any media query value outside ADR 0010's list, on a container query without its comment, and on a Tailwind breakpoint other than the three steps; the one-off values removed, the gutter and the hero's side fade made fluid; a Playwright sweep of every page in French and English, from 320 to 1920 px, run on every pull request that changes code in its own CI job, checking for sideways scroll, overflow, clipped text and overlapping regions; and the fixes it called for: the header's logo showing its emblem alone where the bar is short of room, and chips wrapping their text only when wider than their line.
